# Evidence

`source.json` binds the measured solver source files and executables to
SHA-256 hashes. The build identifies its base commit; the source hashes
identify the local correction tested on top of it.

`cpu_first_growth.csv` contains selected per-iteration readbacks from the
original solver, using the default 50-iteration monitor and force cadence.
The original cell number is the zero-based input index before the RCM
permutation. Fluent IDs in this contiguous native file are one greater. `rank_term` is 0 for
the fastest cell, 1 for the largest momentum-source magnitude and 2 for the
largest absolute mass defect. `rank_within_term` gives its position among the
five recorded cells for that term. The final three columns are the pressure-only
source, reconstructed from the face pressures and oriented face areas.
The other source columns include the transpose-stress contribution too.
The trace completes iteration 308 and the next iteration fails.
Velocity, pressure, k and omega are the fields after the recorded iteration.
Gradients and source terms are the momentum assembly inputs which drove that
iteration, before its pressure correction. They are not presented as a new
steady residual evaluated at the exported fields.
Temporary readback instrumentation was removed before committing.

`prism_regression.log` records the new two-prism operator regression on CPU
and Metal. The full quick-tier count includes this test.

`summary.json` is generated by `../analyze.py` from completed benchmark
records. A failed run has no reported drag prediction. Finite runs retain
their convergence flags; missing results remain missing.

`first_equation.json` records the equation-labelled CPU/Metal reproductions
and equality with the earlier original monitor histories after excluding
time. Both first reject nonfinite input in omega, after much earlier
pressure-force growth. Diagnostic binaries and source overrides were removed
after capture; they never changed the final solver files.

The compressed logs and histories preserve original failures and completed
candidate runs. `incident_metal` is an earlier arithmetic-equivalent control;
`candidate_metal_simplec` is the fresh final-artifact result used in the table.

`slow_comparison_raw_summary.json` retains the supplied comparator's nonzero
result, full case counts and changed values. Its 266 unmatched CLI identities
contain volatile INFO. `slow_comparison_cli_context.json` contains the complete
supplemental comparison after only those context fields are normalized by
`../compare_cli_context.py`. The original XML files are not committed.
