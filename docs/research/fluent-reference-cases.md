# Fluent reference cases

Audit: 2026-10-30. Numerical source: `a0c5caa6079cdd7ccd299ac093d9c9b18373c989`, this isolated checkout, Apple M4 Pro, CPU and Metal. No solver, linalg, runtime or app source changed. Downloaded content was parsed only.

## Result

The audit found **no additional pair that the current solve adapter can run**, including with the named `wfgc` approximation. There are useful new reference assets, but they are blocked by actual reader/physics/settings restrictions. The most useful next target is the **Re=40 laminar cylinder**: a published converged external-flow solution, WFGC explicitly off, with 640 wall-region quads and 25,100 triangles. It separates laminar wall/flux behaviour from SST and WFGC once the 2D laminar/legacy-data path exists.

Downloaded and verified **132 files, 1,391,780,991 bytes** (the exact current total is in the ledger; compressed and decoded forms are both counted), including **74 case variants** and **43 explicit case/data combinations**. Some entries are duplicate representations or intermediate/unsteady results; they are not 43 independent converged reference flows. All 43 pairs were sent through `kutta inspect` and strict, then named-WFGC solve admission. Only the existing V6 elbow was admitted, with WFGC approximation. No new accuracy test can honestly be promoted yet. V6 and its strict failing gates remain unchanged.

### Support status after case coverage (branch `t3/ad404a5c`)

The audit above is unchanged as a record of `a0c5caa`. Since then, standard k-epsilon, laminar, standard pressure, SIMPLE, distance-weighted flux and classic steady iteration have been adapted, along with two named approximations (`compressibility`, `ke-options`). **15 of 43 pairs now run** (main: 1, V6). Strict admission is still 0 of 43. Only two new pairs have a converged Fluent state to compare with: `elbow_param` (velocity L2 0.93%, pressure drop 0.91%, wall force 0.34%) and the nozzle (1.62%, 0.52%, 0.62%), both on CPU and Metal. Those are now slow-tier gates. The elbow-2 snapshots and PPTX are unconverged Fluent states. The Dash data belong to the PPTX water run, not the Dash air case. Details, evidence and open limits are in [the case coverage report](../../validation/results/case_coverage/REPORT.md). Rows below marked "runs" were updated with that report.

## Download identity and trust

The canonical [`fluent_reference_manifest.tsv`](../../validation/fluent_reference_manifest.tsv) records every local path, byte count, SHA-256, pinned URL, licence and extraction transform. Each containing directory has a `SOURCE.md` with the same download evidence. Gzip-decoded members and ZIP members have their own local hashes; a compressed filename alone is not a content identity. Direct and compressed versions can differ even at the same uncompressed byte count. Large downloads and derived VTUs remain gitignored. Only small provenance, code and textual evidence are committed.

## Seeded and cold V6 readback

`kutta solve` ran **1,200 iterations** on CPU and Metal, seeded from Fluent and cold from the stored hybrid initialization. Every run used explicit `--approximate wfgc`. All produced finite exports, but `summary.json` truthfully reports `converged: false`, `stop_reason: iteration_limit`: the CLI has no exposed case convergence criterion. Iteration completion is not physical agreement. The approximation notice embedded in every output contains historical measurements; the numbers below are fresh readback of these four exports.

The comparison executable [`bench_fluent_reference.cpp`](../../bench/bench_fluent_reference.cpp) recreates deterministic RCM cell identity, checks adjacent summary case SHA-256, maps VTU fields back to source cells, and applies the same unweighted relative L2 and face-zone conventions as V6. It reinitializes a solver at the exported final fields **without iterating** to reconstruct boundary pressures/loads. Its wall loads were independently checked against every component in each CLI `forces.csv` (tolerance 1e-10 absolute). Pressure drop is the combined area-weighted inlet pressure minus area-weighted outlet pressure. Saved wall shear is integrated force on the fluid and is negated for force on the wall. The source has zero report definitions; there is no saved lift/drag report comparison to invent.

The fresh errors miss V6 thresholds: velocity and pressure drop <0.5%; seeded maximum field L2 <0.1%; wall shear/total <0.5%. ## Reproduce and verification

```sh
cmake -S . -B build -G Ninja -DKUTTA_REQUIRE_HDF5=ON
cmake --build build -j 8
python3 tools/forensics/reference_cases.py --download
python3 tools/forensics/reference_cases.py --inspect --probe
python -I tools/forensics/reference_metadata.py  # h5py/numpy environment
./build/kutta-tests --test-suite-exclude=slow
./build/kutta-tests --test-case='Fluent research downloads*'

./build/kutta solve validation/fluent_examples/mixing_elbow/mixing_elbow.cas.h5 \
  --data validation/fluent_examples/mixing_elbow/mixing_elbow.dat.h5 \
  --backend metal --iterations 1200 --approximate wfgc --out build/reference-metal-seeded
./build/bench_fluent_reference \
  validation/fluent_examples/mixing_elbow/mixing_elbow.cas.h5 \
  validation/fluent_examples/mixing_elbow/mixing_elbow.dat.h5 \
  build/reference-metal-seeded/result.vtu metal
KUTTA_V6_ITERATIONS=1200 KUTTA_V6_BACKEND=metal ./build/kutta-tests --test-case='FV V6*'
```

Omit `--data` for the cold run; substitute `cpu` for CPU. The current checkout has no `inspect --json`; its existing text interface was used. The audit script writes structured observations around that command without modifying the app. `--probe` is only one-step admission and cannot certify convergence. `--download` restores missing files; an existing hash mismatch fails rather than overwriting it.

Quick tier: **165/165 tests, 7,340,075 assertions pass**, with the downloaded original mesh corpus actually present. The initial unregistered-download failure was reproduced, then fixed by adding explicit ledger path/size expectations; unknown downloads still fail. Original geometry/count/orientation assertions remain intact. The additional slow integrity test checks optional downloads against all 132 recorded source SHA-256/size identities: **264/264 assertions pass**. Absent external files skip explicitly. This is an integrity test, not a new numerical acceptance gate. No additional pair meets the prerequisite for a permanent physical accuracy test today.

Evidence: [`quick-final.log`](../../validation/results/fluent_reference_cases/quick-final.log), [`integrity.log`](../../validation/results/fluent_reference_cases/integrity.log), [`v6-gates-metal.log`](../../validation/results/fluent_reference_cases/v6-gates-metal.log), the four `v6-*.solve.txt` / `*.compare.txt` / `*.forces.csv` / `*.summary.json` / `*.residuals.csv` files, [`metadata.json`](../../validation/results/fluent_reference_cases/metadata.json), and [`probes.json`](../../validation/results/fluent_reference_cases/probes.json).
